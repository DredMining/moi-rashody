# Технический аудит приложения «Мои расходы»

Дата проверки: 18 октября 2026 года. Проверенная версия репозитория: `8e926ec` (`main`, совпадает с `origin/main` до этой правки).

## А. Общая оценка проекта

Это статическое PWA без серверной части. Основная разметка, стили и логика находятся в [index.html](./index.html); отдельные файлы — симулятор iPhone [iphone.html](./iphone.html), service worker [sw.js](./sw.js), манифест [manifest.webmanifest](./manifest.webmanifest), локальные шрифты и изображения. Прикладные записи хранятся в `localStorage` браузера устройства; синхронизации с GitHub в приложении нет.

До проверки отслеживаемые файлы были чистыми, HEAD — `8e926ec`. Существующий неотслеживаемый файл `.github/voice.md` не изменялся.

Подтверждённых ошибок расчётов, сохранения, безопасности или разметки в текущем срезе не найдено. Обнаружена и исправлена одна низкоприоритетная визуальная проблема: видимая полоса прокрутки у основного контейнера. Критических, высоких и средних открытых дефектов — 0.

В приложении уже присутствуют два более ранних исправления защиты данных. В ходе этого аудита их ключевое поведение повторно проверено изолированными синтетическими данными.

## В. Что исправлено

- В [index.html](./index.html) добавлены `scrollbar-width: none`, `-ms-overflow-style: none` и правило `::-webkit-scrollbar`. Поведение прокрутки не менялось.
- Этот актуальный отчёт сохранён в [AUDIT_REPORT_2026-10-18.md](./AUDIT_REPORT_2026-10-18.md); предыдущий отчёт оставлен как исторический и помечен ссылкой на текущий.

Проверка текущего кода также подтвердила, что ранее внесённые меры по сохранности данных остаются в проекте:

- Повреждённое значение `expenses-v1` копируется под отдельный ключ до новой записи. Если резервировать исходный текст не удалось, приложение отказывается перезаписывать его.
- Изменения, объединённые через `store.batch`, сохраняются одной операцией: при отказе записи сохранённый снимок не меняется. Связанные операции возврата/закрытия долга и начисления закята в исходнике объединены в пакетную запись.

## Г. Что осталось

- В текущей среде нельзя было открыть приложение в браузере: доступная вкладка не была расшарена, встроенный браузер отсутствовал, а Chrome вернул `ERR_BLOCKED_BY_CLIENT` при открытии локального адреса. Поэтому визуальный результат CSS, сообщения консоли и реальные пользовательские сценарии после изменения не подтверждены браузером.
- В репозитории нет `package.json`, установленного проектного линтера или автоматического набора тестов. Новые зависимости не устанавливались.
- Данные в `localStorage` и экспортируемые JSON-копии не шифруются приложением. Это свойство текущей архитектуры; записи остаются локальными в пределах браузерного origin.
- CSP в [index.html](./index.html) разрешает `'unsafe-inline'` для скриптов и стилей. Подтверждённого пути XSS при статическом просмотре не найдено; ужесточение CSP можно сделать отдельно при переносе inline-кода в файлы или на nonce/hash.
- Проверка физического iPhone/Safari, Android, экранного диктора, квоты хранилища и параллельной записи из нескольких вкладок не проводилась.

## Д. Результаты тестирования

### Успешно проверено

- JavaScript в двух встроенных блоках [index.html](./index.html), встроенный скрипт [iphone.html](./iphone.html) и [sw.js](./sw.js) синтаксически корректны.
- Упрощённая проверка статической HTML-разметки: 496 тегов, несоответствий вложенности не найдено; 135 статических `id`, повторов нет.
- JSON [manifest.webmanifest](./manifest.webmanifest) разбирается; все 21 уникальный локальный ресурс основной страницы и PWA существуют. Две локальные ссылки симулятора [iphone.html](./iphone.html) также существуют.
- Размеры PNG соответствуют назначениям: иконки 192×192, 512×512 и 180×180; splash-изображения 1320×2868.
- Шесть граничных случаев парсера сумм прошли: формат с тысячными пробелами и копейками; лишние копейки; неверная группировка; сумма с категорией; неоднозначное число после суммы; текстовый суффикс без пробела.
- Четыре изолированных сценария хранилища прошли: сохранение повреждённого текста; отказ перезаписывать его, если резервирование невозможно; отсутствие частичного изменения при ошибке записи пакета; совместное сохранение связанной записи и долга.
- `git diff --check` завершился с кодом 0. Git вывел только предупреждение о преобразовании окончаний строк LF/CRLF.

### Проверено с замечаниями

- CSS новой полосы прокрутки проверен по исходнику; браузерная проверка отображения недоступна.
- Динамические шаблоны приложения используют `innerHTML`; в просмотренных шаблонах имена, заметки и другие пользовательские строки проходят через `esc()`. В [index.html](./index.html) не обнаружены `eval`, `document.write`, внешние скрипты, `fetch` или `XMLHttpRequest`. Service worker обращается только к текущему origin.
- Удаление поля поиска в «Записях» не считается случайной регрессией: это отдельный явный коммит `d87ca16` «Убрать поле поиска записей».

### Не проверено

- Запуск и ручное прохождение всех форм и кнопок в браузере, проверка консоли, импорт/экспорт резервной копии и фактическая офлайн-работа service worker.
- Проверка адаптивной разметки на разных реальных ширинах и устройствах.

## Е. Финальное заключение

По статическому анализу проект находится в рабочем техническом состоянии. В проверенном коде не обнаружены открытые критические, высокие или средние дефекты; ошибки синтаксиса и отсутствующие локальные ресурсы не найдены. Исправлена только визуальная полоса прокрутки. Главные ограничения заключения — отсутствие браузерного прогона и формального тестового набора. Для подтверждения интерфейсной правки достаточно открыть приложение на телефоне и прокрутить экран; данные для этого не нужны.

Изменения оставлены локально. Публикация и отправка в GitHub не выполнялись до подтверждения владельца.

## Дополнение: последующая правка интерфейса долгов

После первичного аудита, по отдельной просьбе владельца, выполнено ещё два изменения в [index.html](./index.html):

- Кнопки общего возврата в карточке должника уменьшены с 34 до 28 px по высоте; основная получила мягкий акцентный фон, вторичная — более спокойное оформление без рамки.
- «Изменить» для долгов теперь открывает отдельное центрированное окно и для долгов, которые должны мне, и для долгов, которые я должен. Окно использует существующий менеджер диалогов приложения; закрывается крестиком, фоном, «Отмена» и Escape, после закрытия возвращает к исходной карточке или списку.

После этой правки синтаксис обоих скриптов `index.html` прошёл повторную проверку. Статически подтверждены центрированная разметка окна, обработчики закрытия, возврат фокуса через менеджер диалогов и отсутствие формы редактирования внутри строки долга. Синтетическая HTML-строка в имени экранируется. Размеры кнопок проверены по CSS. Визуальный браузерный прогон по-прежнему недоступен в этой сессии.
