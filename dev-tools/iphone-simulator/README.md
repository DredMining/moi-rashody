# Симулятор iPhone 18 Pro Max

Инструмент разработчика для «Моих расходов»: виртуальный телефон, внутри которого работает настоящее приложение (не снимок и не копия интерфейса). Само приложение симулятор не меняет: `index.html`, `sw.js` и данные остаются как есть.

## Запуск

В терминале VS Code, из папки проекта:

```
node dev-tools/iphone-simulator/server.js
```

Откроется отдельное окно Chrome с телефоном. Адрес симулятора: **http://localhost:8800/simulator/**

Другие способы:

- двойной щелчок по `dev-tools/iphone-simulator/start-simulator.cmd`;
- в VS Code: меню **Terminal → Run Task… → «iPhone Simulator: запустить (окно Chrome)»**.

Остановить сервер — `Ctrl+C` в его терминале. Нужен только Node.js, устанавливать ничего не надо.

| Параметр | Что делает |
| --- | --- |
| `--browser` | открыть во вкладке обычного браузера, а не в отдельном окне |
| `--no-open` | ничего не открывать, только напечатать адрес |
| `--port 8801` | другой порт (если 8800 занят) |
| `--root <папка>` | показать приложение из другой папки |

### Телефон рядом с кодом в VS Code

1. Запусти задачу **«iPhone Simulator: запустить для вкладки в VS Code»** (или команду с `--no-open`).
2. `Ctrl+Shift+P` → **Simple Browser: Show** → вставь `http://localhost:8800/simulator/`.
3. Перетащи вкладку вправо от кода. В узком окне панель настроек прячется — открывается кнопкой справа вверху.

Simple Browser встроен в VS Code, платных расширений не нужно. В самом VS Code я это не проверял (проверено в Chrome и во встроенном браузере Claude). Если во вкладке что-то не так — пользуйся отдельным окном Chrome: оно ставится рядом с VS Code так же.

### Автообновление

Сохранил `index.html` — приложение в телефоне перезагружается само (примерно за полсекунды). Если в этот момент в приложении набран текст, перезагрузка ждёт: метка вверху скажет «Файлы изменились», нажми «Перезагрузить». Если сервер остановить и запустить снова, симулятор подключится сам.

## Что есть в панели

- **Приложение** — адрес (находится сам; вручную можно указать только `localhost` или `127.0.0.1`), перезагрузка.
- **Вид** — «Телефон» или «Только экран» (переключается без перезагрузки приложения), ориентация, масштаб. «Авто» вписывает телефон в окно; «100%» показывает точка в точку — так мелкие подписи самые чёткие, а сцена прокручивается, если телефон не помещается.
- **Корпус** — четыре цвета, показ Dynamic Island и его развёрнутое состояние (нажатие по самому «острову» делает то же).
- **Система** — оформление iPhone (тёмное → «Чёрный и бордо», светлое → тёмно-синий вид), время, заряд, сеть, Wi‑Fi.
- **Что получает приложение** — переключатель плотности 3x (по умолчанию выключен) и измеренные в окне приложения размеры, плотность, безопасная зона, частота монитора.
- **Сбросить настройки** — всё к стандартному.

## Данные

Приложение в симуляторе живёт по адресу `localhost:8800/app/` — у него своё отдельное хранилище, сначала пустое. Записи с телефона сюда не попадают. Чтобы посмотреть на свои данные, загрузи резервную копию (`.json`) через «Деньги → Данные и резервная копия». В окне Chrome и во вкладке VS Code хранилища разные.

## Устройство

| Файл | За что отвечает |
| --- | --- |
| `server.js` | сервер: приложение по `/app/`, симулятор по `/simulator/`, сообщения «файл изменился» |
| `index.html`, `simulator.css` | разметка и вид: сцена, корпус, экран, панель |
| `simulator.js` | собирает части вместе |
| `components/settings.js` | настройки и их сохранение |
| `components/device.js` | профиль телефона (размеры, отступы), масштаб и ориентация |
| `components/app-frame.js` | экран с приложением: подключение, перезагрузка, имитация среды телефона |
| `components/system-ui.js` | строка состояния и Dynamic Island |
| `components/control-panel.js` | панель настроек |
| `start-simulator.cmd` | запуск двойным щелчком |

Сервер слушает только этот компьютер (`127.0.0.1`), отдаёт файлы только на чтение и не отдаёт скрытые папки (`.git`, `.claude`). В экран телефона браузер не пустит ничего, кроме локальных адресов.

## Откуда цифры

Проверено по странице Apple (поиск 11.11.2026): корпус 163,4 × 78,0 мм, экран 6,9″, 2868 × 1320 px, 460 ppi, до 120 Гц, цвета Black, Silver, Glacier, Burgundy, корпус алюминиевый.

Допущения (для 18 Pro Max не опубликовано, взято от iPhone 17 Pro Max с тем же экраном):

- 440 × 956 точек при 3x — совпадает со снимком экрана с телефона (1320 × 2868);
- безопасная зона: портрет — 62 сверху, 34 снизу; альбом — 20 сверху и снизу, по 62 слева и справа;
- Dynamic Island 126 × 37, в 14 точках от верха; радиус углов экрана 62;
- расположение кнопок и оттенки корпуса подобраны на глаз.

Все эти числа лежат в одном месте — `components/device.js` и начало `simulator.css`.

## Чего симулятор не умеет (ограничения Windows и Chrome)

- **Это Chrome, а не Safari.** Движок другой: шрифты системы, эмодзи, размытие и мелкие детали вёрстки могут отличаться; ошибки, которые бывают только в Safari, здесь не видны. Последнее слово — за настоящим телефоном.
- **Касания.** Мышь даёт нажатия и перетаскивания (горизонтальные жесты приложения работают), но это события мыши: touch-событий нет, а подсветка при наведении срабатывает. Настоящие касания приложение получает на сенсорном экране или при включённой эмуляции в Chrome: `F12` → ⋮ → More tools → Sensors → Touch → Force enabled. Проверено через отладочный протокол Chrome (касания доходят до приложения, вкладки открываются); сам пункт меню я не нажимал.
- **Оформление.** Chrome не даёт сменить системную тему для одной рамки. Симулятор ставит приложению признак `data-theme`, как оно само делает при смене оформления iPhone. Вид меняется полностью, но значок ☀️/🌙 в приложении остаётся прежним, а `prefers-color-scheme` — как в Windows. Если нажать кнопку темы в самом приложении, оно держит свой выбор и после перезагрузки (как на телефоне) — пока снова не нажмёшь «Тёмное» или «Светлое» в панели.
- **Безопасная зона.** В Chrome на компьютере она всегда нулевая, поэтому симулятор подставляет значения телефона в стили открытой страницы (в блоках `<style>`; файлы не меняются). Если приложение открыто с другого адреса (например, через Live Server), подставить нельзя — панель об этом скажет.
- **Плотность 3x выключена по умолчанию.** Приложение видит экран 440 × 956, но с плотностью монитора, а не 3x. Причина: при включённой плотности стрелка «Выбрать элемент» в панели Claude подсвечивает не то место — Chrome сообщает ей положение элемента ровно в три раза меньше (измерено 11.11.2026). Переключатель «Плотность пикселей 3x» есть в панели: включай его, когда нужна проверка именно в 3x, и выключай перед работой со стрелкой. На чёткость картинки он почти не влияет. `screen.width` и `screen.height` в любом случае показывают размер монитора.
- **Мелкий текст при уменьшении.** Телефон высотой 986 точек вписывается в окно, и при масштабе меньше 100% самые мелкие подписи (например, названия вкладок внизу) занимают 8–9 пикселей и выглядят мягко. Это не дефект приложения: кнопка «100%» или окно побольше показывают их чётко.
- **Полоски «Домой»** внизу экрана нет: убрана 11.11.2026, в симуляторе она не нужна. Место под неё (34 точки снизу) приложение оставляет, как на телефоне.
- **120 Гц.** Анимации идут с частотой монитора (она показана в панели) и не быстрее.
- **Время, заряд, сеть, Wi‑Fi** меняют только значки. Дата внутри приложения настоящая, выключенный Wi‑Fi связь не обрывает.
- **Режим «с экрана Домой».** `navigator.standalone` здесь не задан: приложение ведёт себя как открытое в браузере (например, файл сохраняется загрузкой, а не через «Поделиться»).
- **Клавиатура iPhone** не появляется и экран не поджимает. Нет системных жестов, вибрации, упругой прокрутки.
- **Dynamic Island** в развёрнутом виде — демонстрация: приложение им не управляет.
- **Service worker** работает как на телефоне. При автообновлении сразу подхватывается страница приложения; другие файлы (иконки, манифест) — со второй перезагрузки.
